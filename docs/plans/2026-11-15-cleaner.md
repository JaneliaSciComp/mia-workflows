# The cleaner: implementation plan

**Goal:** a scheduled sweep that finds stuck subjects, names service problems, and resolves what it can.

**Spec:** [`docs/specs/2026-11-15-cleaner.md`](../specs/2026-11-15-cleaner.md) (v0.3). Built on the branch
`cleaner`, in the four steps of its §6; each step is committed when its tests pass.

**Architecture:** the rules are pure functions over plain dicts (`mia_buffers/cleaner.py`); one activity gathers
the evidence, opens and advances cases, and writes its report (`mia_buffers/sweep.py`, run by the `MiaCleaner`
workflow on a schedule); cases are rows of the ledger; every change to a subject goes through buffer-api's
action routes as the actor `cleaner`.

## Calls made here (the spec's §7)

- **No workflow per case.** A case is a ledger row holding its remaining steps. Each sweep advances every open
  case as far as it can; a step that must wait (a job not yet dead, autodev not yet answering, a retry not yet
  due) leaves the case where it is for the next sweep. One sweep runs at a time (the schedule skips an overlap),
  so two sweeps never work one case, and the row survives a restart.
- **Temporal is read through buffer-api**, whose dispatcher already has a client per namespace: `GET /health`
  (queues, schedules, the workers' commits), `GET /run/<kind>/<number>` (run id, failing workflow task, pending
  activities), `GET /runs` (open runs by type).
- **A round's jobs are its job records**: the records under the round's workspace directory that have no end,
  each checked against the cluster by job id.
- **Service findings are the sweep's report** (a kv row, like the keeper's), not cases.
- **`cleaner.mode` is `report` when the config has no `cleaner:` block**, so merging this changes nothing until
  the operator writes `mode: act`.
- **The worker's commit** is `git rev-parse HEAD` in the checkout the package was imported from, read when the
  worker starts; the checkout's is the same command at sweep time.

    # {"what": "quiet" | "stopped", "rule": <name> | None, "seen": <sentence>}

def leftovers(...) -> list[dict]                                              # step 3

# a case, as stored and served
{"id": int, "kind": str, "number": int | None, "key": str, "rule": str, "state": str,
 "opened": float, "updated": float,

## Steps

**1. See.** Config; `cases` table and routes; `/cleaner`, `/workers`, `/runs`, wider `/run` and `/health`;
`cleaner.py` findings and sightings; `run_sweep` in report mode; `MiaCleaner`, schedule, workers' commits; the
Cleaner view and the banner. Tests: `tests/test_buffers_cleaner.py` (one per finding, one per sighting class
with the incident it comes from), `test_buffers_ledger.py`, `test_buffers_api.py`, `test_buffers_dispatch.py`,
`test_buffers_ui.py`.

**2. Repair.** `stop` for datasets, `recheck`, the revision check on every action that carries one, `stop` by
run id; the guards (a person's action drops the case; the first step carries the sighting's revision); the
state repairs and the left-over job; the kill before a `go`. Tests: api (each refusal), sweep (each repair
against fakes; a go is not sent while a job lives; a person's go drops the case).

**3. Resolve.** The snippets client on the buffers worker; `snippets_go`, `revise`, `close`, `await_autodev`;
passing cause, fixed since, input changed, host not approved, record gap; the left-over snippet work; the
limits (remedies per week, hands off, a request's go). Tests: one per rule, one per limit.

**4. Diagnose.** The agent job (workspace, prompt, `outcome.json` read as untrusted and reduced to menu steps),
`report_defect`, mia-data's advice from a `cleaner` go. Tests: the reducer drops what is not on the menu; a
case whose remedy did not help is diagnosed once, then needs a person; replay test for the mia-data patch.

## Review focus

- A sweep while a worker is down or behind opens no case for that worker's subjects.
- A `go` is never sent while a job of the ended round lives, nor after a person acted on the subject.
- A request's `go` is refused by the cleaner itself when it would start a dataset round.
- Anything read from a job, an issue or a comment reaches a timeline entry or GitHub neutralized.
- A sweep that fails half way leaves cases a later sweep can continue (every step keyed).
